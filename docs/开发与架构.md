# 开发与架构

本文面向想阅读、修改或提交代码的贡献者。项目没有构建步骤、没有包管理器依赖，修改后刷新浏览器即可看到结果。

## 1. 技术栈

| 层 | 实现 |
|---|---|
| 页面 | 单个 `index.html`，原生 HTML/CSS |
| 模块 | 原生 ES Module，无打包器 |
| 绘制 | Canvas 2D（音网、圆圈、四声部动画） |
| 声音 | Web Audio API 实时合成，无音频文件 |
| 存储 | 仅 `localStorage` 保存圆圈模式 |
| MIDI | 项目内手写 SMF format 1 编码器 |
| 本地服务 | Windows PowerShell `HttpListener` / Python 标准库 |
| 部署 | 任意静态托管；附带 GitHub Pages workflow |

不依赖 React、Vue、D3、Tone.js、Vite、Webpack、Node 或任何 CDN。

## 2. 目录与模块

```text
index.html                 页面骨架、工具条、侧栏、进行条
assets/css/app.css         设计变量、布局、组件、响应式细节
assets/js/core.js          乐理内核
assets/js/audio.js         Web Audio 合成器
assets/js/tonnetz.js       Tonnetz 音网与音级圈
assets/js/satb.js          严格四部和声分析
assets/js/midi.js          MIDI 文件生成
assets/js/app.js           应用控制器与状态
launcher.ps1               Windows 启动、端口探测、打开浏览器
lite-server.ps1            Windows 回环静态服务器 + /api/ping
stop-server.ps1            仅停止本目录的服务器
serve.py                   跨平台零依赖静态服务器
```

### `core.js` — 乐理内核

- 音名、音级、等音拼写与调号；
- 和弦模板与识别；
- 调式定义与 T / S / D 功能分析；
- 输入解析（和弦、音名、音集）；
- 音集理论：标准型、原型、音程向量；
- 试听排列（voicing）。

它是纯函数模块，不依赖 DOM，适合单独测试。

### `audio.js` — 合成器

- 钢琴、正弦、管风琴、弦乐四种音色；
- `playChord` 用于普通和弦/进行；
- `playVoicing` 用于严格 SATB 的实际音高；
- 卷积混响、压缩与主音量；
- 首次用户操作后 `AudioContext.resume()`。

### `tonnetz.js` — 可视化

- `TonnetzView`：无限平移/缩放的三角形网格、点击命中、选择填色、音集凸包、四声部动画；
- `FifthCircle`：五度圈与十二平均律圈共用的绘制和交互；
- 使用 `ResizeObserver` 与 `devicePixelRatio` 适配高 DPI；
- 不直接保存业务状态，状态由 `app.js` 传入。

### `satb.js` — 严格四部和声

1. 为每个和弦生成符合音域、声部次序、间距与重复音规则的 SATB 候选；
2. 用动态规划在整条进行上寻找硬性规则违规最少、声部进行最平滑的路径；
3. 输出四声部音高、问题点、复核项、修改建议；
4. 无严格路径时返回 best-effort 近似，并标记 `strictOk = false`。

硬性规则包括平行五/八度、外声部隐伏五/八度、声部超越、交叉、音域、间距、导音重复等；导音/七音解决、跳进等作为软性提示。

### `midi.js` — 导出

- SMF format 1，480 TPQ；
- 流行模式：1 个钢琴轨；
- SATB 模式：4 个声部轨，Choir Aahs（program 52）；
- 4/4，每和弦 4 拍，速度取当前 BPM；
- 不依赖第三方 MIDI 库。

### `app.js` — 控制器

- 维护 `state`（调性、选择、进行、播放、SATB、显示开关）；
- 绑定 DOM 事件、快捷键与路由参数；
- 将状态推给 `TonnetzView`，将和弦推给 `audio`；
- 解析进行、驱动播放定时器、打开 SATB/MIDI 弹窗；
- 唯一的全局入口：`window.TN`。

## 3. 数据流

```text
用户输入
  │
  ├─ core.parseInput ──► selection { pcs, bass, chord, fn, set }
  │                              │
  │                              ├─ app.refreshUI ──► TonnetzView.setState
  │                              ├─ audio.playChord / playVoicing
  │                              └─ “加入进行” ──► steps[]
  │
  └─ 编辑列表 ──► parseSequenceText ──► steps[]
                                      │
                                      ├─ 播放：selectStep / playStepAt
                                      ├─ SATB：analyzeSatb(steps, { key, tempo })
                                      │        └─ voices[] ──► 网格动画 / MIDI
                                      └─ 导出：buildMidi(steps, { mode, voices })
```

调性变化时：

```text
state.key = makeKey(tonic, mode)
  ├─ keySpell(key)          → 音名拼写
  ├─ harmonicFunction(...)  → T/S/D、罗马数字、副属/借用
  ├─ TonnetzView.setState   → 着色、调号、圆圈旋转
  └─ refreshSatbMode        → 四声部重新计算
```

## 4. 状态与持久化

`app.js` 顶部的 `state` 是单一状态源，主要字段：

| 字段 | 含义 |
|---|---|
| `naming` | `reference`（音名）或 `integer`（0–11） |
| `keyTonic` / `keyMode` / `key` | 当前调性 |
| `selection` | 当前和弦/音集 |
| `steps` / `activeStep` | 进行与当前环节 |
| `playing` / `loop` / `tempo` | 播放状态 |
| `satbMode` / `satb` | 四声部网格与结果 |
| `satbSpeed` / `satbHistory` | 动画速度与残影次数 |
| `circleMode` | `fifths` 或 `chromatic` |

只有 `circleMode` 写入 `localStorage`，键名为 `tonnetz-lite:circleMode`。这是刻意的：项目不做账号、云同步或自动保存。

## 5. 扩展指南

### 5.1 增加一种和弦

需要同时修改两处，否则“能识别”和“能输入”会不一致：

1. `core.js` 的 `CHORD_TEMPLATES`：增加用于分析和显示的性质、后缀、中文名、音程与优先级。
2. `core.js` 的 `QUALITY_MAP`：通过 `addQ()` 增加输入别名。

例如增加 `add2`：

```js
T('add2', 'add2', '加二和弦', [0, 2, 4, 7], 4)
addQ(['add2'], [0, 2, 4, 7]);
```

随后在 `docs/输入语法.md` 补充表格与测试用例。

### 5.2 增加一种调式

在 `core.js` 的 `MODE_DEFS` 中增加：

```js
{ id: 'ionianSharp6', name: '...', short: '...', group: 'major', intervals: [...] }
```

调式选择器会自动读取 `MODE_DEFS`。检查：

- 主音选择与圆圈旋转；
- `harmonicFunction` 对调内/调外和弦的判断；
- SATB 的导音与功能分析；
- 深链参数 `mode=<id>`。

### 5.3 修改 SATB 规则

规则与候选生成集中在 `satb.js`。建议：

- 先写一个最小进行（2–4 个和弦）作为回归样例；
- 分别验证 `ok`、`strictOk`、`issues`、`warnings`、`suggestions`；
- 不要只改“禁止”而忘记给出可操作的提示；
- 保持“硬性规则”和“软性建议”的区分。

### 5.4 增加 UI

`app.js` 负责 DOM 与事件，`tonnetz.js` 负责画布。新增交互时：

1. 在 `state` 中增加字段；
2. 在 `refreshUI()` 或对应 render 函数中同步；
3. 如需持久化，明确写出键名并更新隐私说明；
4. 检查窗口 resize、高 DPI、键盘可达性与移动端宽度。

## 6. 编码约定

- 使用 UTF-8；中文标点与音乐符号（♭、♯、→、–）可以直接写在源码/文档中。
- 2 空格缩进；模块使用 `export`，不使用全局变量（`window.TN` 是唯一调试入口）。
- 乐理数据与 UI 文案尽量分离；不要把和弦表散落在多个文件。
- 新增输入写法时，优先复用 `parseInput`，不要在 UI 层另写解析器。
- 不引入运行时外部依赖；如确需开发工具，放入 `devDependencies` 并在文档说明。
- 修改 SVG/Canvas 绘制时同时检查 1x 与 2x 缩放。

修改后至少手动验证：

- [ ] 直接访问 `/` 能加载，Console 无 404/JS 异常；
- [ ] 点击三角形能选择、填色、发声；
- [ ] 输入 `Cmaj7`、`Am7/E`、`C E G`、`[0,2,4,5,9]` 均正常；
- [ ] 输入 `F#dim7`，并在进行编辑器中写 `F#dim7 | B7 | E`，升号不被当成注释；
- [ ] 切换调性后功能色、调号、圆圈方向正确；
- [ ] 五度圈/十二平均律圈切换后点击音级仍可加入音集；
- [ ] 进行可播放、暂停、循环、逐环切换；
- [ ] 严格 SATB 至少验证一个绿色案例与一个红色案例；
- [ ] 四声部网格可显示、播放、调节速度与残影；
- [ ] 两种 MIDI 均可下载；严格无解时按钮禁用；
- [ ] `?tonic=7&mode=major&seq=G%20%7C%20Em%20%7C%20C%20%7C%20D` 能打开预设；

- [ ] 页面无外部网络请求（Network 面板只显示本地资源）。

## 8. 性能与兼容性

- 音网只在状态变化/动画帧时重绘，不为每个节点创建 DOM。
- `ResizeObserver` 负责画布尺寸；高 DPI 下按 `devicePixelRatio` 缩放。
- 进行播放使用 `setTimeout` 链，切歌/暂停时清理计时器。
- 目标浏览器为现代 Chromium/Firefox/Safari；不支持 IE。
- 移动端未专门适配；如要改进，优先处理工具栏换行、侧栏折叠与触摸手势。

## 9. 安全边界

- 所有逻辑在浏览器本地执行，没有服务端 API（除 `/api/ping`）。
- 本地服务器只读静态文件，不提供上传、写入或目录执行。
- 不要为了“方便”把 `serve.py` 绑定到 `0.0.0.0` 后暴露到公网。
- 用户输入通过 `textContent`/转义进入 DOM；新增模板字符串时继续使用 `esc()`。
- 不引入会注入第三方脚本的 CDN 小部件。
